# Встраивание 3D-просмотрщика моделей в Garnika

Задача: менеджер открывает карточку заказа, прикладывает файл модели БАЗИС (`.b3d`) и видит изделие в 3D — может покрутить, кликнуть по детали, открыть ящики и фасады.

Модуль написан и проверен. Ниже — что подключить и куда.

---

## Файлы

| Файл | Куда | Зачем |
|---|---|---|
| `bazis-calc.js` | в проект | разбор `.b3d`: геометрия, материалы, анимация |
| `garnika-model-viewer.js` | в проект | сам просмотрщик, импортирует `bazis-calc.js` |
| `materials.json` | Supabase Storage или в бандл | цвета и пути текстур, 2856 записей, 728 КБ |
| `bazis-calc.worker.js` | опционально | для крупных моделей, см. раздел про фоновый поток |

Модули — обычный ES без сборки и без зависимостей в стиле остального кода Гарники. **three.js подгружается сам** с CDN при первом открытии, отдельно подключать не нужно.

---

## Минимальная интеграция

```js
import { mountViewer } from './garnika-model-viewer.js';

const viewer = await mountViewer(containerEl, {
  buffer,                       // ArrayBuffer файла .b3d
  materials,                    // разобранный materials.json
  onSelect: part => renderPartCard(part),
});

// при закрытии карточки заказа — ОБЯЗАТЕЛЬНО
viewer.dispose();
```

Контейнер должен иметь заданную высоту и `position: relative` — модуль вставляет в него canvas с `position:absolute; inset:0`. Размер отслеживается через `ResizeObserver`, ничего дёргать вручную не надо.

**`dispose()` не опционален.** Без него остаются висеть цикл отрисовки, обработчики на `window` и буферы видеокарты. Открыл десять заказов — браузер начал тормозить. Вызывать при закрытии модалки и при переключении на другой заказ.

## Полный API

### Опции `mountViewer(el, opts)`

| Опция | Тип | Смысл |
|---|---|---|
| `buffer` | ArrayBuffer | файл `.b3d` |
| `materials` | Array | содержимое `materials.json` |
| `onSelect` | fn(part\|null) | клик по детали, `null` при снятии выделения |
| `background` | number\|null | цвет фона, `null` — прозрачный. По умолчанию `0x14171a` |
| `textureBase` | string | адрес каталога текстур; без него детали красятся цветом |
| `textureTileMm` | number | сколько мм покрывает плитка текстуры, по умолчанию 1200 |
| `onTexture` | fn(ok, fail) | прогресс загрузки текстур |

### Методы

```
stats                      // { parts, panels, profiles, area, sizeMm, movable, withTexture, ... }
anims                      // [{ id, kind: 'rotate'|'slide', name, limit, travel, salonType }]
animOf(id)                 // параметры узла + текущее положение
setOpen(t, id?)            // 0..1; без id — все узлы сразу
getOpen(id?)
play(seconds = 2.5, id?)   // плавно открыть и закрыть; без id — вся модель
stop()
flip(id) / flipAll()       // развернуть направление открывания
setPartVisible(index, on)
hideSelected() / isolateSelected() / showAll() / hiddenCount()
setLayer('wire'|'profiles'|'room', on)
setView('iso'|'front'|'plan'|'left') / fit()
dispose()
```

### Что приходит в `onSelect`

```js
{ index, animId, name, node, material, kind,        // kind: 'Панель' | 'Профиль'
  length, width, thickness,                          // мм
  area, edge,                                        // м², пог. м
  paintFaces, cutouts, texAngle }
```

`index` — устойчивый идентификатор детали в этой сессии, его можно связывать со строкой спецификации. `animId` не `null`, если деталь входит в подвижный узел — тогда в карточке имеет смысл показать управление анимацией.

## Как это выглядит в интерфейсе

Рабочая раскладка проверена на стенде (`Стенд проверки просмотрщика.html` — открывается двойным щелчком, можно посмотреть живьём и подсмотреть разметку).

**Область просмотра.** ЛКМ вращает, колесо приближает, ПКМ или Shift сдвигает, клик выбирает деталь. На тач-устройствах работает щипок.

**Карточка детали** справа: габарит крупно, ниже имя, узел, материал, площадь, метраж кромки, число вырезов. Кнопки «Скрыть» и «Только эта». Когда что-то скрыто — «Показать все» со счётчиком.

**Анимация.** Общий ползунок «Открыть всё» и кнопка «Показ» — для демонстрации клиенту. Управление конкретным узлом показывается **в карточке выбранной детали**, если у неё есть `animId`: свой ползунок, «Показ» и «Развернуть». Списка всех узлов делать не нужно — в кухне их дюжина с одинаковыми именами, искать в списке неудобно.

**Клавиши:** `H` скрыть выбранную, `S` показать все. Учтите русскую раскладку — `Р` и `Ы`.

## Хранение моделей

Логика та же, что у остальных вложений заказа.

1. Бакет `models` в Supabase Storage, **приватный**.
2. Менеджер прикладывает `.b3d` к заказу, путь вида `orders/{orderId}/{filename}.b3d` пишется в таблицу.
3. При открытии просмотрщика файл скачивается через подписанную ссылку и передаётся как `ArrayBuffer`.

```js
const { data } = await sb.storage.from('models').download(path);
const buffer = await data.arrayBuffer();
```

Размеры моделей: от 2 до 23 МБ. В базу их класть не надо, только в Storage.

## Текстуры — можно позже

Сейчас детали красятся цветом из базы материалов: у 394 записей есть настоящий HEX, остальные подбираются по названию.

Чтобы включить текстуры, достаточно передать адрес каталога:

```js
textureBase: 'https://ПРОЕКТ.supabase.co/storage/v1/object/public/textures'
```

Ничего больше не меняется: пути к текстурам **уже лежат** в `materials.json` (1165 записей), а углы поворота читаются из самой модели.

**Держите этот адрес в настройках приложения, а не в коде** — рядом с `S.settings.speeds`. Тогда включение текстур станет правкой значения, а не выкладкой новой версии.

## Особенности, которые важно не «упростить»

Всё это уже учтено в модуле. Перечислено, чтобы при рефакторинге не сломать.

**Знак толщины.** У профиля толщина бывает отрицательной — это направление выдавливания. Геометрия сдвигается на `p.t`, для длины берётся модуль. Фильтр `> 0` потеряет 48 профилей из 179.

**Порядок трансформации.** Положение считается по матрице **до** её обновления. Обратный порядок даёт габарит вдвое больше — эта ошибка уже была допущена и исправлена.

**Ветка истории правок.** Внутри `.b3d` лежат прежние состояния изделия. Без их пропуска расчёт завышается в полтора раза: 576 деталей вместо 365. Фильтр по `ActiveIndex` / `StartName` уже стоит в парсере.

**Поверхности нулевой толщины** — это оболочка помещения из замера, а не детали. Модуль их не показывает, но считает в `stats.roomSurfaces`.

**Экранирование.** В Гарнике 49 мест с `innerHTML` и есть функция `esc`. Имена деталей и материалов приходят из файла модели — прогоняйте их через `esc` или используйте `textContent`. Это не паранойя: содержимое `.b3d` задаёт кто угодно.

## Чего я не проверял

Отрисовку. Геометрия, матрицы, анимация и разбор проверены headless в Node с настоящим three.js — ошибок построения и NaN нет. Но WebGL в моей среде отсутствует, поэтому саму картинку я не видел.

Под вопросом остаётся **направление поворота фасадов**: ось и угол взяты из модели и точны, а знак мог оказаться противоположным — тогда дверца распахнётся внутрь корпуса. На этот случай есть `flip(id)`, и кнопка «Развернуть» в карточке детали. Если при проверке окажется, что разворот нужен всегда — скажите, поменяю знак по умолчанию.

Меши фурнитуры (направляющие, петли) в просмотрщик не заложены: их разбор и упрощение — отдельная работа, а для оценки компоновки они не нужны. Панели и профили дают узнаваемое изделие.
